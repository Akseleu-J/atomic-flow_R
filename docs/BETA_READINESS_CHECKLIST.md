# BETA_READINESS_CHECKLIST — калибровка системы перед бета-тестом

Дата: 09.11.2026. Контекст: план владельца — бета 300–500 мест, окно 96 ч на участника,
self-host, подача через форум (интейк → персональная ссылка), фидбек в follow-up-форум.
Бета = стресс-тест продакшн-уровня, результаты пойдут в аргументацию (B2B).

Аудит-метод: hands-on «как свежий тестер» (публичный клон → README → CLI → doctor),
плюс ревизия публичного дерева r/main. Дашборд Studio в этом заходе руками не гонялся —
отдельный заход.

## T1 — Бета-блокеры: слой первого контакта

Ядро в порядке (hold/unknown/no-replay, evidence-контракты, doctor, serve с токеном на non-loopback).
Ломается не ядро — «первый час» тестера.

- [ ] **T1.1 Дистрибуция артефактами, не исходниками.** Public-клон по сети уже оборвался
      («invalid index-pack output», репо 5.4 MB — сеть нестабильна). Для 300–500 тестеров:
      `af-win64.zip` + Linux-тар (сборка Linux доказана Kaggle-циклом), SHA256SUMS, ссылки по
      интейку. Сборка из исходников тестерам не предлагаем (mingw64-PATH, -j1 — tribal knowledge).
- [ ] **T1.2 Time-gate беты (96 ч).** Минимум для волны 1: билд-время expiry — бинарник отказывает
      запускаться после даты, в `af doctor`/`--version` виден срок. Сервер лицензий не нужен.
- [ ] **T1.3 README под артефакт беты.** Сейчас README ведёт в Python-линию (`pip install`, `atomic`),
      а продукт беты — `af` + Studio: вилка двух бинарей без указателя. Одна точка входа: скачать →
      распаковать → `af doctor` → первый task → фидбек. Python-линию — отдельным разделом.
- [ ] **T1.4 CLI-тексты.** У обязательных `--root-id/--file/--replacement` ПУСТЫЕ описания help;
      `root_id` — внутренний жаргон; нет примеров команды; нет `af task list` (чем возобновлять/смотреть
      задачи?). Пройтись по всем подкомандам.
- [ ] **T1.5 `af evidence export`** — одна команда → один пакет (verification report + journal-срез +
      doctor + версия) для форума фидбека. Сегодня пакеты собирает только код, CLI-команды нет.
- [ ] **T1.6 `af doctor` — человеко-режим.** Сейчас JSON-only: для бандла хорошо, для человека нет.
      Формат по умолчанию — читаемый чек-лист с подсказками-фиксами, `--json` для бандла.
- [ ] **T1.7 Budget для CLI-пользователя.** У `af task run` нет бюджет-флагов/переменных: как тестер
      ставит потолок live-прогона и читает отказ admission? Нужен явный путь (флаг/env + понятное
      сообщение об отказе) — для беты это и есть демо безопасности.
- [ ] **T1.8 First-run wizard.** Live-конфиг сейчас — ручной `providers.json` / env. Для 300–500
      участников это сотни тикетов: `af init` — шаблон провайдера + 创建 budget + проверка `doctor`.
- [ ] **T1.9 Crash-захват.** Panic → локальный crash-лог, попадающий в `evidence export`;
      без этого фидбек «у меня упало» теряет половину ценности.
- [ ] **T1.10 Studio hands-on аудит** — отдельный заход (браузер): онбординг дашборда, выбор
      воркспейса, понятность состояний задач/hold.

- [ ] **T2.1 Task-паки:** 3–5 готовых сценариев с ожидаемым исходом (из P-слайсов) — чем участник
      займёт 96 часов. Отдельный пакет «сломай нас» для волны 1.
- [ ] **T2.2 Интейк-анкета** (клики): ОС, роль (инженер/исследователь), опыт с CLI-агентами, цель.

- [ ] **T2.3 Форма фидбека**, привязанная к метрикам: время до первого успеха, hold-случаи, ложные
      срабатывания чекера, что бросили и почему. + шаблон «приложи evidence export».
- [ ] **T2.4 Метрики для аргументации:** инсталлы, активации, задачи, holds, фидбеки. Сбор — из
      report-бандлов участников (ручной агрегат), БЕЗ тихой телеметрии: локальность данных — часть
      продаваемой истории безопасности.
- [ ] **T2.5 Лицензия — решение владельца.** Сейчас всё MIT-публично. Для беты допустимо, но

## T4 — Корпоративные требования (B2B-гэпы, таблица владельца от 09.11)

Оценка: все 4 строки реальны для корпоративного заказчика, но ни одна не блокирует бету
инженеры/исследователи (300–500, self-host, 96 ч). Часть уже в роадмапе B2B (Tier 1 microVM
SandboxDriver, N10+ corporate profile). Важная поправка: таблица построена по README
Python-линии и недооценивает ядро — в Rust-линии уже есть behavioral checker (requirement
gate), бюджет-план с hold/unknown/no-replay, evidence-пакеты, честная маркировка уровня
доверия (doctor: local-trusted vs docker fallback).

- [ ] **T4.1 Изоляция выполнения (microVM SandboxDriver).** Роадмап Tier 1 (после Tier 0).
      Firecracker/gVisor — Linux-истории; на Windows — Windows Sandbox / WSL2, выбрать отдельно.
      Для беты — только честная маркировка уровня изоляции в doctor/отчётах (частично есть).
- [ ] **T4.2 Git worktree-режим воркспейса.** Лёгкая версия закрывает класс фейлов «проект
      зависит от .git» на реальных репо тестеров — кандидат в бета-пак. Полная версия
      (подписанные коммиты, ветки, PR в GitHub/GitLab Enterprise) — после беты, рядом с
      N06 publication/cutover.
- [ ] **T4.3 IAM: SSO (OIDC/SAML), RBAC/ABAC на команды.** Корпоративный трек (N10+), не бета.
- [ ] **T4.4 Сканер секретов перед отправкой контекста в LLM.** Минимальная версия дешёвая:
      regex-набор (provider-ключи, AWS, GitHub, private-key заголовки) на pre-send пути +
      `secrets_found` в evidence + политика refuse/redact. Защищает самих тестеров (их ключи
      в providers.json) — КАНДИДАТ В БЕТУ (решение владельца до заморозки пакета).
      SIEM-экспорт (Splunk/ELK) — корпоративный трек.
